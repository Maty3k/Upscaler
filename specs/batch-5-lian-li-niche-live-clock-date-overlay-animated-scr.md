# Batch 5 — Lian Li niche — live clock/date overlay + animated (scrolling/marquee/fade/typewriter) text + save/load shareable .json layouts

**Scope:** Batch 5

## Goal
Add three time/sharing features to the existing Lian Li 8.8" panel builder (upscaler/panel.py + the "Lian Li Screen" tab in app.py): (5A) a per-frame live clock/date overlay rendered with a strftime template; (5B) animated text motion (scroll/marquee/fade/typewriter) that offsets position/alpha/visible-char-count by frame index, including synthesizing N frames from a still source and wrapping for a seamless loop; (5C) save/load panel layouts as self-contained, shareable .json files (PanelParams + overlays, with sticker PIL images base64-embedded) written to ~/.upscaler/panel_presets/, with Download and Upload that fan values back across the existing flat component list. All offline, PIL/ffmpeg only, no new deps.

## Dependencies
- 5B builds directly on 5A: both modify compose_frame's signature (5A adds frame_index/elapsed/now; 5B adds total_frames/fps) and both share the extracted _render_text_layer helper. Implement 5A first, then 5B, to avoid two conflicting refactors of _draw_text_overlay (upscaler/panel.py:262-291) and compose_frame (panel.py:236).
- 5C must come after 5A and 5B because its JSON schema and the fan-back-to-components mapping must include the new clock overlay type (5A) and the text motion fields (5B); serializing before they exist would require a follow-up schema bump.
- All three depend on keeping the flat-component-list invariant in app.py in sync (N_TEXT/_TEXT_FIELDS/N_STICKER/N_CLOCK -> N_OVERLAY_VALS at app.py:497-501, _panel_params at app.py:504-532, _overlay_inputs at app.py:1869-1870, and the wiring at app.py:2077-2111).

## Item 5A — Live clock/date overlay as a new per-frame overlay type  _(effort: M)_

Today compose_frame(src, p, fast) renders each overlay with no notion of time: upscaler/panel.py:236 iterates p.overlays and dispatches 'text'->_draw_text_overlay (panel.py:262) and 'sticker'->_draw_sticker (panel.py:294); text/sticker dicts carry no temporal info. Add a third overlay kind type='clock' whose 'content' is a strftime template (e.g. '%H:%M:%S' / '%a %d %b'). Thread a frame context into compose_frame so the rendered time advances per exported frame. Concretely: (1) extend compose_frame's signature to `compose_frame(src, p, fast=False, *, frame_index=0, elapsed=0.0, now=None)` — keyword-only and defaulted so every existing caller (preview() at panel.py:335, export_still at panel.py:500, mockup at panel.py:380, and tests) keeps working unchanged. (2) In the overlay loop add `elif kind == 'clock': _draw_clock_overlay(canvas, ov, elapsed=elapsed, now=now)`. (3) Implement _draw_clock_overlay: compute the timestamp as `base = now or datetime.now()`; `ts = base + timedelta(seconds=elapsed)`; `text = ts.strftime(ov.get('content') or '%H:%M:%S')` guarded by try/except ValueError (bad strftime codes -> fall back to literal content) so a malformed template can't crash a render; then reuse the exact text-drawing path by building a shallow-copied text-style dict (font/size/color/align/x/y/rotation/stroke/stroke_w taken from the clock ov) with content=text and calling the same rendering code as _draw_text_overlay. Refactor _draw_text_overlay so the glyph-rendering core is shared (extract `_render_text_layer(canvas, content, ov)` and have both text and clock call it) to avoid duplicating the rotation/stroke/positioning logic at panel.py:271-291. (4) In the export frame loop (panel.py:591-596) pass `frame_index=i-1` (0-based) and `elapsed=(i-1)/fps` to compose_frame so the clock ticks across the clip; export_still passes nothing (defaults -> datetime.now() once). (5) In preview() pass elapsed=0 (a static 'now' snapshot) so the editor preview shows a representative time without re-rendering on a timer. Caveat to document in code + UI: the clock is BAKED at export time — a 30s MP4 shows 30s of clock starting from the export moment, it is NOT a real-time wall clock when later played in L-Connect 3 (L-Connect just loops the file). The strftime instant for a still-image PNG/JPG export is the single moment of export. App-level wiring (app.py): add a clock to the overlay slots. Cheapest approach that preserves the flat-list contract: add N_CLOCK=1 clock slot built in panel_mockup_ui's accordion area (app.py:1794-1870) with fields [enabled, template, font, size, color, align, x, y, rotation, stroke, stroke_w] (same 11 fields as a text slot so it reuses the text rendering). Add constants N_CLOCK=1 and _CLOCK_FIELDS=11 near app.py:497-501, extend N_OVERLAY_VALS, and in _panel_params (app.py:504-532) consume the clock slot AFTER the sticker slots and append dict(type='clock', content=template, ...) when enabled. Provide a small dropdown of common templates ('%H:%M:%S', '%H:%M', '%I:%M %p', '%a %d %b', '%Y-%m-%d', '%d/%m %H:%M') as a Gradio Dropdown(allow_custom_value=True) so users can type their own. Because the clock slot's components are appended to _overlay_inputs (app.py:1869-1870), the preview/export/mockup wiring at app.py:2077-2111 picks them up automatically.

## Item 5B — Animated text motion: scroll/marquee, fade in/out, typewriter — driven by frame index with seamless wrap  _(effort: L)_

Add motion fields to the text overlay dict and make _draw_text_overlay honor frame context so text can move/fade/type across an animated export. Today _draw_text_overlay (upscaler/panel.py:262-291) is fully static: it draws content on its own RGBA layer, optionally rotates, then pastes centered at the (x,y)% position. compose_frame iterates overlays with no time input. Plan: (1) Build on 5A's compose_frame(..., frame_index, elapsed, *, fps and total_frames context). For motion we need the loop length, so also thread `total_frames` and `fps` into compose_frame (keyword-only, default total_frames=1, fps=30). (2) Add optional fields to the text overlay dict, all defaulted so still text is unchanged: motion ('none'|'scroll-left'|'scroll-right'|'scroll-up'|'scroll-down'|'fade'|'typewriter'), speed (px/sec for scroll, or cycles for fade), and for typewriter a cps (chars/sec). (3) In _render_text_layer (the shared core from 5A) accept a `motion_ctx` with frame_index/total_frames/fps and compute: scroll -> horizontal/vertical offset = (frame_index/fps)*speed, wrapped modulo (text_extent + canvas_extent + gap) so the string exits one edge and re-enters the other; for a SEAMLESS loop the wrap period must divide evenly into total_frames/fps (snap speed so `period_seconds * fps` frames == total_frames, i.e. one or more whole scroll cycles per clip) — document that non-integer cycle counts will show a jump at the loop join. fade -> alpha = a triangle/sine of frame_index over total_frames (0->1->0) so it fades in and out within the loop and ends where it began. typewriter -> visible_char_count = min(len(content), int((frame_index/fps)*cps)); slice content to that many chars before measuring/drawing, optionally append a blinking cursor block; for a clean loop hold the full string for the tail of the clip. (4) Still-source handling: animated text needs N frames even when the source is a still image. The hold-still branch already exists at panel.py:573-586 (when ffmpeg extracts 0 frames it saves the first frame N times for `hold` seconds). Extend export_animated so that when the user has any animated overlay AND the source is a still (n frames after hold == derived from a fixed duration), we still composite N distinct frames (the source pixels are identical but the overlay motion differs per frame) — this already happens because each c_%05d.png is composited individually at panel.py:591-596; the only change is ensuring N is large enough: when a still source has animated text, default `hold` to a full loop period (e.g. the scroll cycle length or a sane 4s) rather than min(dur,3.0) at panel.py:583, and expose a 'Clip length (s)' number for stills with motion. (5) For scroll wrap-around the layer must be drawn twice (the trailing copy) so as one copy scrolls off, the next is already entering — implement by tiling the text layer along the scroll axis with `gap` spacing and pasting at the wrapped offset. App wiring (app.py): add motion controls to each of the N_TEXT text slots (app.py:1799-1838). New per-slot fields: motion (Radio/Dropdown), speed (Slider), cps (Slider for typewriter). This grows _TEXT_FIELDS from 11 -> 14; update _TEXT_FIELDS, N_OVERLAY_VALS (app.py:499-501), the unpacking in _panel_params (app.py:511) and the dict it builds (app.py:514-518) to include motion/speed/cps, and the slot-collection list at app.py:1837-1838. Because preview() renders a single static frame (frame_index defaults), animated text shows in its start position in the editor; add a small 'animation previews on export' hint, or optionally a preview-frame slider (out of scope — note as open question).

## Open questions
- Should the editor preview animate (e.g. a 'preview frame' slider feeding frame_index into preview()) so users can scrub motion/clock without exporting? Spec assumes a static start-frame preview plus a hint to keep scope down; a scrub slider is a reasonable follow-up.
- Saved layouts: just Download/Upload files, or also a named in-app gallery of saved presets under ~/.upscaler/panel_presets/ rendered with the .preset-active highlight pattern (app.py:1051, 1246-1251)? The prompt emphasizes shareable .json (Download/Upload), so the gallery is optional — confirm desired scope.
- Does Gradio reliably preserve RGBA alpha when programmatically setting a gr.Image(type='pil', image_mode='RGBA') value via gr.update on layout Upload? Needs a manual /verify; if alpha is dropped, sticker cut-outs would composite as opaque after load.
- For seamless scroll the spec snaps speed to whole cycles per clip; should the UI auto-snap (and show the effective speed) or just warn? Auto-snap is cleaner but changes the user's entered number.
- Sticker base64 can make layout JSON several MB; should we cap sticker resolution before encoding (e.g. max 1024px) to keep shared files small, accepting a quality trade-off?
